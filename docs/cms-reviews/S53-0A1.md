# S53 review packet — 0A-1 (A1): one parsed operation, then authorization

**Work item (brief):** A1 — CMS operation parsing and permission regression.
**Acceptance gate:** Mixed payloads cannot mutate; read-only actors and
support grants remain read-only; valid clients work.

## Source finding (verified before changing anything)
`app/api/admin/storefront/route.js` (pre-change): the PUT permission derived
from `body.getPage` (`storefront.read` when truthy) while dispatch checked
`body.block` FIRST. A payload `{getPage:"x", block:"hero", value:{…}}`
therefore authorized as a read — which a support actor passes and which
skips the same-origin check (`isWriteAction("storefront.read")` is false) —
and then executed the block mutation. Confirmed by reading the dispatch
order; now also proven by the regression suite's "was a silent mutation"
case (which fails against the old handler shape).

## Change
- NEW `lib/admin/cms-api.js`: `parseStorefrontOperation(body)` extracts
  EXACTLY ONE operation from {block+value | block+reset | page | deletePage
  | getPage}; zero ops → 400 `NO_OPERATION`, several → 400
  `AMBIGUOUS_OPERATION` — both BEFORE authorization. The permission then
  derives from the parsed op (getPage → storefront.read; all else →
  storefront.write, keeping requireAdmin's same-origin check), and only the
  parsed op is dispatched (no re-reads of raw body keys). Revision/CAS
  semantics are byte-identical ("revision" present = CAS, absent = no
  check); conflict (409 + current) and validation (422 + errors) responses
  unchanged. Handler returns plain {status, body}.
- `app/api/admin/storefront/route.js` is now a thin NextResponse wrapper
  over the lib handler (the extraction exists so the suite can exercise the
  REAL dispatch path without Next's `@/` module alias, which plain-node
  scripts cannot resolve).
- Behavior deltas beyond the fix: empty body is 400 before auth (was 400
  after auth); mixed payloads are 400 for every actor (previously the
  mutation ran). All single-op shapes — which are the only shapes
  `components/admin/cms/api.js` ever sends (verified by reading it) — are
  untouched.
