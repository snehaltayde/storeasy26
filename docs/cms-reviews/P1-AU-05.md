## Fix round 1

An independent reviewer found one blocker and four minor items. All five were checked against the code and all were right.

- **Blocker: ordinary words typed into FAQ answers and rich sections were lost, with a 200.** Fixed: the save is now refused and the message quotes the words. See "Words the sanitizer would remove".
- **The suite did not run the components.** Fixed: `ContentPage` now renders in the suite, and `PageEditor`'s load and save logic runs on stand-in hooks. Load mapping moved to `formSections` in `pageSections.js`.
- **The http image link message used internal wording.** Reworded. The reviewer's suggested text contained `https://`, which the suite's own plain-words rule forbids, so it reads: `section N: this image link isn't secure. Use a link that starts with https, or choose an image from your library.`
- **A section holding only a zero-width character counted as content.** Fixed for the emptiness check only. Stored words keep these characters, because Indian scripts and emoji need them to display correctly.
- **Each save added another `rel` to a link with a target.** Fixed in `sanitizeAttrs`. A row that already holds duplicates shrinks on its next save. Round 2 changed how the words are merged.

### Words the sanitizer would remove

`validatePageSections` now compares what the founder typed with what the sanitizer returns, using `wordsLostBySanitizing` in `lib/sanitize.js`. Any visible words missing from the result refuse the whole save with the row untouched, and the words stay in the form.

Before, through the real handler (reviewer's probe). Now, exact message:

| Typed | Before | Now |
|---|---|---|
| `Free on orders <500 and >100 rupees.` | 200, stored `Free on orders 100 rupees.` | 422 `section 1, question 1: saving would lose these words: "<500 and >". This usually comes from < or > signs. Reword them or remove them, then save again.` |
| `Write to Priya <priya@store.com> any day.` | 200, stored `Write to Priya  any day.` | 422, quotes `<priya@store.com>` |
| `<p>Keep it at a<b and c>d always.</p>` | 200, stored `<p>Keep it at a<b>d always.</p>` | 422, quotes `<b and c>` |
| `<p>Hello</p><noscript>Important founder words</noscript>` | 200, stored `<p>Hello</p>` | 422, quotes `Important founder words` |

Refusal was chosen over encoding the stray `<` in the sanitizer because encoding does not help `<b and c>` or `<priya@store.com>`, which parse as tags. It would also change what every other sanitizer caller stores.

This describes the rule as it stands after the final round.

What counts as words: anything between `<` and `>` that is not real HTML. Real HTML means a known HTML tag name, or a Word tag (prefix `o`, `w`, `v`, `m`, `st1` or `x`, then letters and hyphens), with well-formed attributes. A bare attribute must either start with `data-` or `aria-`, be `autofocus`, `hidden` or `itemscope`, or fit its tag (`required` on `input`, `open` on `details`, `controls` on `video`). A tag the sanitizer strips counts as words when it has no attributes, or only a `/`, and nothing closes it later. The exceptions are `col` and `wbr`, which real HTML holds bare, and a self-closed Word tag such as `<o:p/>`. After `<!` or `<?`, only `<!--`, `<!doctype html`, `<![if`, `<![endif`, `<![cdata` and `<?xml` count as markup. Text inside `noscript`, `svg`, `math` and `object` counts, and so does everything after a `script`, `style`, `iframe` or `template` that is never closed, or a comment that is never closed, because the sanitizer drops it all.

What still saves, because no visible word, link, video or picture address is lost: scripts, styles, comments, event handlers, `javascript:` and `vbscript:` addresses, unknown attributes, an iframe or video with no address. Those keep AU-06's notice.

**3. Security: its own commit, also needed on main. Fixed in `sanitizeHtml`, for every caller.**
- The dangling `<` branch encoded only the first `<`. `< <img src=x onerror=alert(1) ` came back as `&lt; <img src=x onerror=alert(1) `, and the same for `a < b <svg onload=alert(1) ` and `<<img src=x onerror=alert(1)//`. `components/pdp/PdpLayouts.js:37` writes Shopify's description through `sanitizeHtml` into `dangerouslySetInnerHTML`, and the next `>` on the page closes that tag, so the handler runs for shoppers. Every `<` in that remainder is now encoded. Product pages sanitize when they render, so they are fixed as soon as this lands.
- A comment holding `>` was cut at that `>`: `a <!-- private note > do not show --> d` published `do not show --> d`. A comment now ends at its own end, and comes back `a  d`. A comment never closed hides the rest of the input, as it does in a browser. A save refuses that case, quoting the words.
- Proof, in `pnpm test:security`. No HTML parser is a dependency (checked `package.json` and `pnpm-lock.yaml`; `next` bundles `node-html-parser`, which doesn't follow the HTML standard's tag rules), and none was added. The suite holds a small reader written from the standard's tag and comment states. For 799 unclosed inputs (47 payloads with tabs, newlines, form feeds, slashes and uppercase, times 17 lead-ins) and 20,000 seeded random mixes, it reads the output followed by `</div><p>after</p>` and asserts: no event handler or disallowed tag or attribute, no comment, no unsafe address, nothing left open, the rest of the page intact, and sanitizing again changes nothing. Before the fix this failed on the first affected input.
- Cross-check, one-off and not in the repo: the same 20,799 outputs went through real Chrome's `DOMParser`, headless, on the final code. 0 had a disallowed tag or attribute or lost what follows. As a control, the old sanitizer's output on the same inputs was flagged 1,662 times.
- `lib/sanitize.js` stays free of `node:` APIs, because the storefront runs on the edge runtime.

**4. Minor: an old template could become unusable. Fixed by carrying the section as it was.** `instantiateTemplate` now checks each section on its own. One that passes today's rules is cleaned as before. One that fails goes into the new page exactly as stored. Carrying was chosen over dropping because dropping loses words: the reviewer's section `{kind: rich, heading: "Keep", html: "<p></p>"}` holds a heading. The form is where the founder can act, and the page's Save refuses it with the plain message and its position. Nothing unchecked reaches shoppers, since this only fills the form and Save checks everything.

**Small items that took a minute.**
- A template name over 80 characters is refused, not cut: `the template name is too long (81 characters, the limit is 80)`.
- More blank entities count as empty: `&ensp;`, `&emsp;`, `&thinsp;`, `&zwj;`, `&zwnj;`, and `&nbsp` with no semicolon. `#xa0` and `#x200b` now have test cases.
- Reviewer's sanitizer cases added: `<b =x>`, `<template>x</template>`, `<iframe/>words</iframe>`.

Where this differs from the reviewer's suggestions: `VALUELESS_ATTR` became a per-tag table, with `hidden`, `autofocus`, `itemscope`, `data-` and `aria-` allowed on any tag. Picture messages differ from video ones, because "embedded videos" is wrong for a picture.

## Known limits

Deliberately left. Each was confirmed by running it through `validatePageSections` on the final code unless it says otherwise.

**Content that can still be removed with a 200, the form marked clean.**
- **Parts with no words and no address, or that only run code.** A script, a style, an event handler, a `javascript:` address, an inline `style` such as `background:url(/a.jpg)`, a comment (even one the founder forgot about). AU-06 owns that notice. Until then the editor shows the typed version until a reload.
- **Media forms the refusal doesn't read.** `<video poster="…">` and `<iframe srcdoc="…">` with no address. `<img data-srcset>`, `<img data-lazy-src>` and other lazy-load names beyond `srcset` and `data-src`. A picture inside something removed whole: `<svg><image href="…"/></svg>`, `<noscript><iframe src="…"></noscript>`.
- **A picture with a placeholder.** `<img src="/placeholder.gif" data-src="/real.jpg">` keeps the placeholder and loses the real one, because a usable `src` counts as the picture.
- **`<picture>`.** `<source srcset>` isn't reported, because the `<img>` inside normally holds the picture and pasted pages use this a lot. So `<picture><source srcset="/a.webp"><img alt="A"></picture>` saves with no picture.
- **A typed tag name that is real HTML.** The check cannot tell these from markup:
  - A name the sanitizer keeps: `Use the <code> field` stays as a `<code>` tag, so shoppers don't see that word, though the form still shows it.
  - A real name that something closes later: in `Send <time> and <time>x</time>` the first `<time>` is lost.
  - A real name with well-formed attributes, or a bare attribute that fits it: `<address data-x>`, `<details open>`, `<input required>`, `<a download>` (the `a` tag stays, the word goes), and `<b hidden>`, since `hidden` fits any tag.
  - A closing tag on its own: `</address>` is lost.
  - A Word prefix with letters after it: `<w:sale>Blue</w:sale>` loses the tags and keeps `Blue`.
- **Words inside the real forms that aren't comments.** `<![CDATA[free shipping]]>`, `<?xml free shipping?>`, `<!doctype html free shipping>` and `<![if sale]>` all count as markup, so their words go. Nobody is likely to type these.

**Rows and other paths.**
- **Stored content is not re-cleaned.** `ContentPage`, `FaqSection`, `HomeSections` and `PdpLayouts.js:63` render what was stored at save time. A row that already holds `&lt; <img src=x onerror=alert(1) ` stays that way until saved again, and a row cut mid-comment stays published. Only the product description (`PdpLayouts.js:37`) sanitizes at render. Whether to re-clean stored rows when this lands on main is the owner's call. This branch runs no migration. Not measured: nobody has checked whether any row holds such text.
- **Three callers still cut after sanitizing.** `lib/cms/validate.js:60` and `:200` and `lib/catalog-overrides.js:30` run `sanitizeHtml(…).slice(0, N)`, so a cut can leave an open tag such as `<img alt="x` in what they store. `sanitizeHtml` itself never returns one, and every attribute left is on the allowlist, so a cut can't add a handler, but the page's markup can break. Read from the code, not reproduced in a browser. AU-06 already owns refusing over-limit text in `validate.js`. `catalog-overrides.js` has no owner yet. Cutting before sanitizing would be a one-line fix for each; it was left out as outside this list.
- **Rows saved earlier can be refused on their next save.** The row stays as it was and the message says why. Stored words are never lost by this. A row the old `.slice` cut mid-tag at the limit grows when its dangling `<` is encoded: `section 1: the content is too long (20003 characters, the limit is 20000)`, and the founder has to trim a few characters. A section holding only empty markup or invisible characters is now refused as empty. Below the limit, a cut row saves again with its `<` encoded.
- **Outside the page editor nothing is refused.** See "Related, not fixed".

**Behaviour the founder can see.**
- **A lone `<` is stored encoded.** `Under 5 < 10` saves and shoppers see it as typed, but the stored text is `Under 5 &lt; 10`, so the form shows `&lt;` after a reload. No word is lost. The sanitizer has always done this.
- **Some unusual HTML is refused rather than cleaned.** Custom tags such as `<wix-image>`, namespaced tags outside Word's such as `<fb:like>`, tags with a bare attribute that doesn't fit such as `<div foo>` or `<p required>`, and stripped tags left unclosed such as `<center>x` or `<dd>x`. The message quotes it. A false refusal keeps the text in the form, which is the safer way to be wrong.
- **A false refusal in a comment-like case.** `<noscript><!-- a > b --></noscript>` is refused quoting `b -->`. The word check reads the comment differently inside a removed element.
- **Embedded videos can't be saved at all.** The refusal stops the silent loss. It doesn't add video support. A founder has to link to the video instead.
- **Whitespace is normalized.** Trimming, and joining single line breaks within a paragraph into a space, is the stored shape the editor has always written. No words are lost.
- **A carried template section shows its problem late.** The founder sees the message on Save, not when picking the template. If a template holds a section of a kind the page doesn't know, it also opens now and falls back to a text section in the form. Such a row can't be made through the validator, so this was not tested.
- **In `section N, question M`, M skips untouched blank rows,** so it can read lower than the row's position on screen.

**Test gaps left from the review.** The editor's id adoption after adding a section, loading a headingless template or history version into the stand-in editor, the Save as template button's enabled state, and the dialog's error are not exercised by a test. D4 and D5 cover them in a browser, once run. The security proof reads tags with the suite's own reader, not a browser, and real Chrome only checked it once, by hand. `next build` was not run.

## Deviations from the spec

1. **Refusal covers all four kinds, not only text.** The spec names text. The task asked to fix the same bug elsewhere. A founder who adds a section and leaves it blank now gets a refusal instead of a silent drop. This is visible behaviour, and the copy says so.
2. **Over-limit text in page sections is refused, not cut.** The spec gives this to AU-06, but AU-06's evidence cites only `lib/cms/validate.js`, not the `.slice` calls in `lib/cms/store.js`, and a cut paragraph would break negative 3. AU-06 may later turn the refusal into a field-level flag.
3. **`lib/cms/registry.js:129` also said required.** The spec's evidence did not list it. Changed so the declaration matches the rule.
4. **A text section with a heading and no `body` key now passes.** It was refused before. This follows the relaxed rule and drops nothing.
5. **New file and new suite.** `pageSections.js` exists only so the real conversions can be tested. `test:page-editor` is a suite the spec did not name.
6. **`lib/sanitize.js` changed what it returns in three ways, for every caller.** `wordsLostBySanitizing` and `addressesLostBySanitizing` are new and only `validatePageSections` calls them. What `sanitizeHtml` returns changed for `rel`, as below, and in the security commit: every `<` after the last `>` is encoded, and comments end at their own end. So a Shopify description with a comment that is never closed now loses everything after it, as it would in a browser, where before it showed part of the comment. Word's `<!--[if …]>…<![endif]-->` blocks are now removed whole, where before their inner text leaked out. The `rel` fix applies to every caller, including the shopper product page: a link with a target now has exactly one `rel`, holding the words it came with, minus `opener`, plus `noopener noreferrer`. Before, both attributes were kept and browsers used only the first, so an incoming `nofollow` used to win over the safe words and now sits beside them. Words are lowercased. `test:security` and `test:content` stay green.
7. **Words the sanitizer would remove are refused here, not left to AU-06.** The spec's AU-06 covers HTML the sanitizer removes. The reviewer's finding, which this follows, is that plain words are a negative 3 failure, so the owner may want to confirm the split. The same reasoning moved over-limit refusal in.
8. **`scripts/test-storefront.js` changed by one assertion.** It pinned the old image message (`image src`) and now looks for `image link`.
9. **The suite compiles with Next's SWC instead of the runner in spec 8.15.** It is a stopgap with no new dependency. When the JSX runner lands, the render tests and drills D1 and D2 should move to it.
10. **Link and image addresses are refused here, not left to AU-06. The owner should confirm this and decide on phone links.** A founder who types a `tel:`, `sms:`, `whatsapp:`, scheme-less or relative address now gets a refusal, where before the link silently died. That is visible behaviour. `SAFE_URL` was left alone because it applies to every caller, including Shopify descriptions on the product page. So click-to-call and text links still can't be saved. Adding `tel:` and `sms:` is one line and both are safe, but it widens the sanitizer's allowlist, so it is the owner's call. WhatsApp has an https form (`wa.me`) that already works.
11. **Empty markup is refused as blank.** This is older than the branch and loses nothing, so it is not strictly negative 3. It was cheap, and it stops an empty block being published. A section already stored that way is refused on its next save until the founder removes it or adds content.
12. **Video, sound and lazy-loaded picture addresses are refused here, not left to AU-06. The owner should confirm this.** AU-06 isn't built and AU-05 ships alone. A founder who pastes a video embed now gets a refusal, and cannot save an embed at all until video is supported.
13. **The security fix and the comment fix are in this branch.** They are outside AU-05's spec text. The commit is separate so it can land on main first.
14. **Template name over the limit is refused, not cut.** Small, and the same rule as the rest of the branch.

Spec citations were checked at `939d630`: `PageEditor.js:68-69,239,260`, `store.js:315` and `ContentPage.js:49-50` were all accurate.
