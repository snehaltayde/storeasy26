## What was built

- **`components/admin/cms/editorLayout.js` (new, no JSX, no imports).** The editor's numbers in one place: the editor routes, tree 224px, inspector 288px, canvas padding 8px, breakpoints 1280 and 1024, the three devices (Mobile 375, Tablet 768, Desktop 1280), how a device's page fits the space (`frameFit`, `frameStyles`), the caption (`fitCaption`) and the expected pane widths at any window width (`editorGeometry`). The shell, the unit suite and the drill all use these numbers.
- **`components/admin/cms/EditorShell.js` (new).** `EditorShell` is the editor's own layout outside the console's cap: a compact top bar (menu button, Sections button below 1280, breadcrumb, title, surface tabs, the caller's actions), a notices strip, and the panes: tree on the left, preview in the centre, inspector on the right. From 1024 wide it fills the window below anything the console shows above it, so the page itself never scrolls and each pane scrolls on its own. Below 1280 the tree renders in a drawer (the console's own `Drawer`, a native modal `<dialog>`), and in exactly one place at a time. `DeviceSwitch` is the Mobile, Tablet and Desktop buttons, with `aria-pressed` and a tooltip giving the width. `PreviewCanvas` measures its own space, renders the page at the device's real width, shrinks it as a whole when it does not fit, and shows a caption such as `Desktop, 1280 px wide, shown at 71% to fit`.
- **`components/console/nav/ConsoleShell.js`.** On editor routes (`/admin/storefront/designer` and anything under it) the shell renders no sidebar, no 1024px cap and no page padding. The navigation folds into the existing drawer, which the editor opens from its menu button through the new `useConsoleNav()`. Every other console page renders exactly as before. The founder's saved sidebar preference is untouched.
- **`components/admin/cms/Designer.js`.** Uses `EditorShell`. The tree and inspector lose their card wrappers, because the panes have their own dividers. The preview uses `DeviceSwitch` and `PreviewCanvas`, and the old `DEVICES` list with `width: "100%"` is gone. Save, the save status, the conflict and error banners, preview start and refresh, and the PreviewBridge handshake are unchanged. The banners are now the shell's children; their lines are byte for byte the same.
- **`components/admin/cms/SurfaceDesigner.js`.** The same shell with no tree: preview in the centre, the Template, Modules and "Also on this page" cards in the inspector. Before a product or collection is picked, the centre asks for one and there is no empty inspector. The cards moved into a `const inspector`, so their lines are re-indented; `git diff -w` shows them unchanged.
- **`components/console/Drawer.js`.** A `closeLabel` prop, default `Close menu`, so the tree drawer's close button reads `Close sections`.
- **`components/admin/cms/DesignerTabs.js`.** Its bottom margin is dropped, because it now sits in the top bar.
- **`scripts/test-editor-layout.js` + `test:editor-layout` (new suite, in the gate).** Unit tests of the numbers, and rendered tests of the real `ConsoleShell`, `Designer` and `SurfaceDesigner`, compiled with Next's SWC and rendered with `react-dom/server`.
- **`scripts/drill-editor-layout.js` + `drill:editor-layout` (new, not in `pnpm test`).** The browser drill. It needs a running harness and Chrome. It launches its own headless Chrome with a throwaway profile, signs in with the harness's local test password (read from `.design-env`, never printed), measures, optionally saves screenshots, and exits 1 on any failed check. No dependency was added: it uses Node's global `WebSocket`.

## Deviations from the spec

1. **Desktop is a real 1280px page, shrunk to fit and labelled.** "Device buttons set real widths": before, Desktop was `100%` of whatever space was left, so at 1024 the store would have drawn its tablet layout. Now the page always renders at 1280, so the store shows its desktop layout, and when the pane is narrower it is shrunk as a whole and the caption says by how much (71% at 1440, 59% at 1280, 56% at 1024). The acceptance allows "visibly scaled and labelled". **Owner's call:** 1280 or 1440 as "Desktop", and whether text shrunk to 56–71% is readable enough. No "actual size" toggle was added.
2. **The console navigation folds away completely on the designer, behind a menu button, rather than shrinking to the 64px icon rail.** With the rail, 1440 − 64 − 224 − 288 leaves 864px, and the 900px target at 1440 cannot be met with the spec's minimum tree and inspector widths. **Owner's call** whether that trade is right.
3. **Narrower side panes than before.** The tree is 224px (was 256) and the inspector 288px (was 320 on home, 352 on product and collection), just over the spec's 220 and 280, to give the preview the room. One visible cost: on the product and collection designers, the Template select's chosen text is cut off ("Follow store default (Classic"). The open list shows it in full.
4. **Below 1024 the inspector goes under the preview.** The spec says nothing below 1280 except the drawer. Side by side, 1024 is the narrowest width where the preview keeps 600px.
5. **Only the designer routes get the full-width layout.** HomeEditor, PageEditor, Navigation and the rest keep the console layout until ED-02 brings them into one editor. `EDITOR_ROUTES` in `editorLayout.js` is the one list to extend.
6. **The page header became a compact top bar.** The title is 16px, not the console's 24px. The breadcrumb shows only its first step ("Storefront ›"). **The description line ("Compose the home page visually. Everything saves as a draft — publish from Publishing.") is now read to screen readers only, not shown.** The save toast still says "Saved as a draft — publish from Publishing". Owner's call whether that sentence should stay visible.
7. **The editor fills the window and the panes scroll on their own,** from 1024 wide up. Before, the whole page scrolled. Below 1024 the page scrolls as before.
8. **Two new script entries.** `test:editor-layout` joins the gate. `drill:editor-layout` is outside it, because it needs a server and a browser. The spec's planned Playwright runner (8.15) does not exist yet; the drill is a stopgap over Chrome's own protocol, with no new dependency, and should move to that runner when it lands.

## Known limits

- **The store inside the frame was never drawn on the harness.** Every frame showed the storefront's "Something went wrong" page: the storefront group is `runtime = "edge"`, and on file databases the edge reader logs `control plane unavailable`. No runtime flip was made, temporary or committed. So these are unverified: how the store looks at 1280 shrunk to 56–71%; click-to-select through a shrunk frame (browsers map clicks through CSS transforms, but the PreviewBridge never connected and the status stayed at "Connecting…"); highlight and scroll into a shrunk frame; live unsaved-edit refresh keeping the device and scale. These are browser drills for after the harness fix.
- **Thin margin at 1440.** The Desktop preview is 912px there, 12px over the 900 target. A wider tree or inspector would break it (M1). The drill runs Chrome with `--hide-scrollbars`. From 1024 up the page has no scroll, which the drill checks, so no page scrollbar appears; the panes' own scrollbars on systems with classic scrollbars (Windows, or macOS set to always show them) sit inside the fixed tree and inspector widths and were not measured.
- **Below 1024 the page scrolls,** so with classic scrollbars the preview loses about 15px (at 768, about 737px, still over 600). Not measured.
- **Phones:** under 616px wide, the preview cannot keep 600px. ED-10 owns phones.
- **The tree drawer shows "Sections" twice:** the drawer's own title, then the tree's heading with Undo and Redo. Harmless, a little redundant.
- **Hydration warning on the product and collection designers, not caused by this branch.** `SurfaceDesigner` reads `sessionStorage` in a `useState` initializer, so the server renders "Pick a product" and the client renders the picked product. React logs "Hydration failed…" and re-renders on the client. Seen with the original `SurfaceDesigner.js` swapped back in too. Left alone, because it is not layout; reading the saved context in an effect would fix it.
- **During client-side navigation into the designer** the console's generic loading skeleton shows full width, with no padding, until the page arrives. Not measured; a designer-shaped `loading.js` would fix it.
- **Safari, iPad and touch** were not tried. The shell uses `dvh` units, `ResizeObserver`, `matchMedia(...).addEventListener` and the native `<dialog>`'s focus return, all in Safari 15.4 and later. See the owner's checks.
- **The render tests compile with SWC and stub** routing, toasts, pickers and the API client, the same stopgap as AU-05. They check markup, order and classes, not real layout. The browser drill is the measured proof.
- **`next build` was not run.** The dev server compiled all three designer routes and the storefront pages it served.
- **Zoom, very tall or very short windows, and right-to-left** were not measured. All drill runs used 900px tall windows.
- **One drill run failed for the drill's own reason:** the console-menu check clicked before React hydrated. The drill now waits for the preview frame first (commit `test(cms): ED-01 drill waits for hydration…`); the editor was not changed for it. The same commit keeps a console URL out of `test:shopify-boundary`'s Admin REST scan, which had flagged the drill.
