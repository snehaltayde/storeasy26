# S53 review packet — B2: pickers in real forms

**Work item (brief):** B2 — reusable pickers in current forms.
**Acceptance gate:** Replace handles in home curation, catalog pins and
upsells first; then links and variant-driven surfaces.

## What was built
- **components/admin/cms/RefPicker.js** (new): one dialog (MediaPicker
  pattern, native <dialog> focus trap) over GET /api/admin/refs — debounced
  search, keyset "Load more", thumb/title/mono-handle/price rows, amber
  Unavailable badges, product counts; multi mode hydrates pre-selected ids
  on open (order kept), shows MISSING selections as danger chips that pass
  through Confirm (never silently dropped), move up/down + remove, dedupe,
  max caps with visible counts, Confirm disabled while hydration is
  loading/failed; single mode confirms on click; loading/error-retry/empty
  states; "Catalog synced <time>" freshness line. Wrappers: ProductPicker,
  CollectionPicker, and a two-step VariantPicker (product → its COMPLETE
  variant list with options + SKU; never auto-picks).
- **Adopted, with each form's wire format preserved byte-identically**
  (mapping at the form boundary only):
  - Upsells (sourceHandle + ordered targetHandles strings): Choose buttons
    append picked handles; typed-handle fallback kept for unsynced entries.
  - Collection pins (CatalogAdmin: {collection:{handle, pinnedHandles[]}}):
    collection picker + member-filtered product picker; hand-typed
    collection handles resolve to ids on demand with an honest error state.
  - Home collections curation (collections_index HANDLES, null=automatic):
    per-list CollectionPicker through the existing validation/dedupe/caps;
    manual mono fallback kept; hero/sections untouched.
  - FREE_GIFT offer gift (cfg.gift {variantId GID, …}): VariantPicker fills
    variantId/productId/handle/title; manual GID input kept; nothing
    auto-selected.
  - Bundles (CommercePanels items[].variantId): per-component VariantPicker
    fills the variant GID; typed fallback kept.
- Brief correction found by implementation: pins live in CatalogAdmin and
  bundles in CommercePanels (the brief had them swapped); both were in
  scope and each was wired where it actually lives.

## Known, honest limits
- Handle-persisted lists (upsells, pins, home curation) APPEND via the
  picker; their existing text/list stays the ordered source of truth,
  because the ids= hydration contract can't hydrate handles. Migrating
  those stores to ID references is the recorded follow-up (audit: "migrate
  handle-driven input at the persistence boundary") — this slice delivers
  the selection UX without a silent storage migration.
- Id-persisted selections (gift variant, bundle components) do hydrate and
  show missing state.
