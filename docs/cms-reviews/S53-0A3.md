# S53 review packet — 0A-3 (A3): tenant source + auth fallbacks fail closed

**Work item (brief):** A3 — catalog/auth tenant fallback hardening.
**Acceptance gate:** Missing source credentials and lookup failures fail
closed; unrelated-tenant fixtures prove isolation.

## Source findings (verified)
1. `lib/sync.js` catalogSource() used env-fallback credential detection
   (`tenantSecret(key, ENV_KEY)`), and `lib/shopify.js` read
   SHOPIFY_STORE_DOMAIN / STOREFRONT tokens from env unconditionally — a
   platform tenant with no credentials of its own could select the
   "storefront" source and ingest the ENV-CONFIGURED shop's catalog into its
   own database. (Even a tenant WITH its own storefront token never had it
   used: the client only knew env.)
2. `lib/platform/sessions.js` tenantHasMembers/operatorsExist caught lookup
   failures as `false`; `lib/admin-auth.js` and `lib/platform/admin-auth.js`
   treat `false` as "no accounts yet → the retained bootstrap/shared
   password works". A control-plane outage could therefore resurrect
   bootstrap authentication on tenants/platforms with real accounts.
3. `lib/typesense-search.js` productsCollection() fell back to the env/
   default collection ("products") — tenants without their own namespace
   would search (and the sync would index into) one SHARED index.

## Changes
- `lib/shopify.js`: endpoint/authHeaders/shopifyFetch/fetchAllProducts/
  fetchAllCollections take explicit `creds`; a provided creds object is used
  VERBATIM (incomplete → throw; never mixed with env). `creds = null` keeps
  the legacy env store.
- `lib/sync.js`: platform tenants (currentTenant() && id !== "_default")
  detect sources from tenant-OWN config/secrets only; storefrontCreds()
  passes the tenant's own domain + tokens to the fetchers. Env detection and
  env client remain for the legacy/_default store only. indexTypesense skips
  (SQL fallback) when the tenant has no namespace.
- `lib/platform/sessions.js`: tenantHasMembers/operatorsExist now THROW on
  lookup failure. Callers decide: verifyAdminToken and verifyPlatformToken
  DENY on failure (bootstrap only after a SUCCESSFUL zero-rows read);
  adminBootstrapMode reports not-bootstrap on failure; the platform login
  route treats failure as "operators exist" (bootstrap refused).
- `lib/typesense-search.js`: platform tenants resolve their OWN namespace or
  null (→ SQL search); env/default fallback only for the legacy store.

## Compatibility
- Fresh-tenant onboarding (pavos-style) unchanged: a SUCCESSFUL zero-rows
  membership read still opens the bootstrap password (tested).
- Legacy/_default store: all env paths byte-equivalent.
- A tenant that previously "worked" by silently syncing the wrong shop now
  fails with "No Shopify credentials for this tenant" — correct, and the
  connect flow is the fix.
