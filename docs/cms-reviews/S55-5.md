# S55 review packet — Slice 5 (increment): edit≠publish + draft history

**Work item (audit):** Slice 5 — editorial/operational scale (the "basic
author/publisher separation early" part; approvals/changesets later by the
audit's own sequencing).

## What was built
- **storefront.publish** (admin+): staff keep storefront.write (drafts,
  preview) but publish/schedule/rollback/cancel on /api/admin/releases now
  require the new capability. The Publishing screen receives a
  server-computed canPublish (roleAllows in the SERVER page only), disables
  the four actions for non-publishers and explains itself with one
  PermissionNote; preview stays available. BREAKING for staff who
  previously published — that is the point (audit M: "editing and
  publishing share one permission").
- **Draft revision history** (cms_history, migration 0015): every console
  block/page save appends its saved value + actor, capped at 20 per key,
  best-effort (a failed append never fails the save; lib-level writers like
  applyKit/experiments bypass — recorded). Read via the one-op API
  ({history:{kind,key}}, read-gated). Restore is deliberately indirect:
  History dialogs in the PageEditor and the Designer (hero / announcement /
  sections) load a version INTO the editor as an unsaved change — the
  ordinary save path (validation + CAS + a fresh history entry) completes
  it, so restore can never bypass conflict protection. Unreadable entries
  render disabled, never crash.
