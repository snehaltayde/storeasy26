# S54 review packet — Slice 3 (first path): the home-page visual designer

**Work item (audit):** Slice 3 — editor shell plus a full home path.
**Acceptance gate (this increment):** edit → preview → review candidate →
publish → rollback for the HOME surface, through a visual workspace.

## What was built
- **Designer ⇄ preview bridge** (components/preview/PreviewBridge.js):
  mounted ONLY in preview mode (cookie-gated in the storefront layout) and
  INERT until the console iframe performs a same-origin postMessage
  handshake — public pages never ship editor code, and a plain draft
  preview browses normally. In designer mode, clicking a `[data-sec]`
  section SELECTS (navigation swallowed), with hover/selected outlines;
  parent can highlight+scroll a section and trigger refresh after saves.
  HomeSections/hero emit `data-sec` attributes (durable instance ids; an
  inert attribute on public pages).
- **/admin/storefront/designer** (+ "Designer" in the Storefront sidebar):
  three-pane workspace — left section tree (pinned Hero node + one row per
  section: kind icon, Hidden badge, move/hide/duplicate/delete with stable
  focus, registry-driven Add menu, undo/redo), center real-storefront
  iframe (device widths 375/768/desktop, refresh, open-in-tab, honest
  "Preview shows your last save" strip, mint-failure retry), right
  inspector whose controls are GENERATED from the component registry's
  settings declarations (text/number/link/html) — the hero gets its full
  field set. Selection syncs both ways (tree→highlight, preview
  click→tree+inspector).
- Save model: one explicit Save (hero + sections, each with its CAS
  revision; adopt-on-success; preview refresh), the shared ConflictBanner
  per block, 422 banners, reset-to-default behind confirm, dirty guard.
  Duplicates drop the durable id (server mints a fresh instance); new
  sections come from registry defaults.

## Honest limitations (stated in-UI where relevant)
- Preview shows the SAVED draft (refresh-after-save) — live unsaved-edit
  preview is future work, per the audit's own sequencing.
- Buttons, not drag-and-drop. Undo covers sections (HomeEditor parity).
- Highlight no-ops for never-saved/hidden sections (absent from the saved
  DOM). PDP/collection paths and template assignment: next increments.
- The forms-based Home page screen remains alongside the Designer (same
  blocks, same CAS — two views over one draft; retiring it is a product
  call for later).
