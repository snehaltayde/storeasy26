# S53 review packet — B1: resource reference read model

**Work item (brief):** B1 — resource reference and catalog selection read
model.
**Acceptance gate:** Paginated products/collections/variants, selected-ID
hydration, complete variants, no unbounded/N+1 query pattern.

## Source findings (verified)
- The console's only catalog endpoint returned at most 30 products with no
  pagination; the audit's picker contract cannot be built on it.
- The admin sync fetched `variants(first: 50)` with no pageInfo in BOTH its
  full-pull and single-product queries — products past 50 variants were
  silently truncated at the projection, so no selector could honestly offer
  "every real variant".

## Changes
- **Variant pagination** (lib/shopify-admin-catalog.js): both queries carry
  variants pageInfo; `drainVariantTail` (mirroring the existing >250-product
  collection drain) pulls the remainder at 100/page before reshaping, in the
  full pull and the webhook single-product path. `gql` stays injectable.
- **GET /api/admin/refs** (route wraps lib/admin/refs.js — node-safe, exactly
  the cms-api pattern): `type=product|collection|variant`, `q` (title/handle
  contains; products also match variant SKU via one EXISTS subquery),
  keyset `cursor` on (title, id) with limit ≤ 50, `ids=` hydration returning
  the caller's order with explicit `{id, missing:true}` markers (a picker
  shows what the catalog lost, never silently drops it), `collection=`
  member filter for products, `product=` for a product's complete variant
  list (position order, parsed options, SKU, availability), and `syncedAt`
  (max products.synced_at) for honest freshness. One query per request —
  no N+1, no full-catalog scans. storefront.read gated; tenant scope from
  the host-resolved context only.

## Verification (exact commands, local)
- `node scripts/test-refs.js` → **8 passed, 0 failed** on a 60-product /
  60-variant fixture: pagination reaches item 60 with stable order and no
  duplicates; title/handle/SKU search; hydration order + missing markers +
  freshness; ALL 60 variants listed (no 50 cap); collection counts + member
  filter; two-tenant isolation with an overlapping handle (anonymous denied,
  each tenant sees only its own row); unknown type / bad cursor / missing
  product → 400; no cookie → 401.
- `pnpm test:platform-sync` 15 (sync fetchers untouched in behavior for ≤50
  variants) · `pnpm build` compiles.
- Residual, stated honestly: the drained variant tail is proven by the refs
  fixture at the PROJECTION level; a live >50-variant Shopify product has
  not been synced in this environment (no such product exists in the
  connected test shops).
