# S53 review packet — 0A-2 (A2): published reads fail closed

**Work item (brief):** A2 — published-content failure behavior and initial-
release contract.
**Acceptance gate:** Anonymous shoppers never receive drafts because a
release is unavailable/corrupt; preview remains isolated.

## Source finding (verified)
`lib/releases.js` getLiveRelease caught EVERY error as `null` ("pre-migration
tenant"), and `lib/content/resolve.js` treated null as "no release yet →
drafts serve to everyone". A transient control-plane/tenant-DB read failure,
a dangling live pointer, or corrupt release JSON therefore flipped the whole
storefront into draft mode for anonymous shoppers.

## Change
- `lib/releases.js` getLiveReleaseState(): three DISTINCT states —
  `live` (parsed, envelope-validated release) · `none` (release tables
  absent = genuinely pre-migration, or no live pointer = pre-first-publish)
  · `error` (query failure, pointer with no release row, unparseable or
  version-less content). "no such table" is the ONLY error treated as
  `none`, because the tables not existing is the pre-first-publish state.
- `lib/content/resolve.js` contentSource(): preview cookie → drafts
  (unchanged, that browser only); `none` → drafts (documented
  pre-first-publish behavior, unchanged); `error` → throws
  ContentUnavailableError, which the storefront's existing error boundary
  renders. Shoppers get the branded error page, never drafts.
- getLiveRelease() remains as a compat wrapper (error → null) for the
  ADMIN/operator badge surfaces (console layout dot, releases/overview
  pages, platform overview) — an error there shows "never published"-ish
  state, which is a known, admin-only softness recorded here; tightening
  those badges is follow-up polish, not a shopper-safety issue.

## Files changed

- lib/content/resolve.js (fail-closed contentSource + ContentUnavailableError)
