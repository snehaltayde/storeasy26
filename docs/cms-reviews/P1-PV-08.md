## What was built

- **`lib/experiments.js`**
  - `heroVariantFor(experiment, hero, unitId, { preview })`. In a preview it returns the founder's hero untouched, `assignment: null` (so nothing pings) and `notice: { slug, name, section: "hero" }`. Nothing is picked, not even a bucket. Without `{ preview: true }` the code path is the `8968db3` one, unchanged.
  - `isPreviewRequest(request)`: true when the request carries a `_preview` cookie, whatever its value.
  - `conversionUnit(request)`: `null` for a preview request, otherwise the `_unit` cookie.
  - `runningTestsBySection()`: `{ hero: { slug, name } }` for the console's notes.
  - `TEST_SECTION`: which storefront section (its `data-sec`) each test target changes. Only `hero` exists.
- **`app/(storefront)/page.js`**: reads `contentSource()` in the same `tfetch` pass (React-cached, so no extra read) and passes `{ preview: src.preview }`. The ping still mounts only with an assignment, which a preview never has. `<ExperimentNote>` renders inside `[data-sec="hero"]` when there is a notice.
- **`components/preview/ExperimentNote.js`** (new, no hooks, edge-safe): the preview's note, in the same purple as the "Draft preview" bar: *A test is running on this section: "Hero promise test". Some visitors see a different version; the preview shows yours. See the test*. The link goes to the test's row in the console (`target="_top"`); inside the Designer the preview bridge turns a click in the hero into selecting it, as before.
- **`app/api/exp/route.js`**: a request carrying a preview cookie gets `{ ok: true, recorded: false }` before anything is read or written.
- **`app/api/checkout/route.js`**: both conversion units (COD, and online payment after verification) come from `conversionUnit(request)`, so an order from a preview session converts nothing.
- **Designer** (`components/admin/cms/Designer.js`, new `components/admin/cms/TestRunningNote.js`): when a test runs on the hero, its settings open with an info banner, *A test is running on this section. The mark is the row's description (`aria-describedby`), not part of its name, so the button is still named "Hero" (three batch B drills select it by that name).
- **Designer page** (`app/(console)/admin/(authed)/storefront/designer/page.js`): loads `runningTestsBySection()` beside the view; a failed read costs only the note.
- **Experiments screen** (`components/admin/ExperimentsAdmin.js`): each row has `id="exp-row-<slug>"`, the anchor both notes link to. No per-test page exists, so the link opens the list at that row. `exp-row-` keeps it apart from the form's own ids (`exp-slug`, `exp-name`, …).

## Deviations

- **Any preview cookie refuses counting, but only a valid one makes a preview.** The page shows the founder's own content only for a valid, tenant-bound preview token (the existing rule, `contentSource`). `/api/exp` and checkout refuse to count any request that carries a `_preview` cookie, valid or not. Only the console mints that cookie, so a stale or forged one only keeps its own holder out of the counts. A shopper can't be affected. The cost: a founder whose preview session expired (PV-04) sees the live page with a variant, and that view isn't counted. Tested both ways.
- **The tree's "Test running" mark** is beyond the brief, which asked for the note beside the settings. It shows the test before the founder selects the hero. It is the row's description, so the button's name stays "Hero".
- **The link goes to the test's row on the Experiments list**, since there is no page per test. Rows gained `id="exp-row-<slug>"`.
- **Conversions are gated in `app/api/checkout/route.js`**, which the pending payment branch rewrites (see Merge notes).
- **The Home page editor** (`/admin/storefront/home`), which also edits the hero, shows no note. The brief named the Designer; that screen has no preview pane. See Known limits.
- **The preview note uses the "Draft preview" bar's purple**, not the store's tokens: it is preview chrome, and it must read on any brand.
- **`scripts/drills/p1/harness.mjs` changed** (batch B's drill): two finding 1 known markers removed, one relabelled.
- **`scripts/test-copy.js` changed**: its home-page render stubs the two new imports (`ExperimentNote` renders nothing for shoppers; `contentSource` says not a preview).
- No migration, no new dependency.

## Known limits

- **One experiment target exists (hero).** The gate is per serving place: a new target (a section, a module, an offer) needs its own `{ preview }` gate and note. The guard test and `TEST_SECTION` fail or point at that, but they can't write the gate.
- **The Designer learns which tests run when it loads.** A test started, paused or completed while the Designer is open keeps the old note and tree mark until a reload. The preview frame's note is always current (it renders per request).
